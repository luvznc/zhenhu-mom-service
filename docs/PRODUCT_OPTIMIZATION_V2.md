# V2产品优化方案：专业认证、双服务模式、IoT与培训商业化

## 1. 优化目标

将平台从“持证护士撮合”升级为“医护背景母婴护理人才培养与标准履约平台”，解决三个核心问题：

1. 护理背景不等于月嫂能力，必须补齐营养月子餐、产褥生活照护、家政规范和家庭沟通。
2. 家庭对餐饮、家务、班次和健康监测需求不同，服务范围必须可选、可签约、可验收。
3. 平台需要持续的人才供给和收入来源，培训、考核、认证与订单质量应形成数据闭环。

## 2. 业务架构

`人才招募 -> 基线测评 -> 分层培训 -> 实操考核 -> 平台认证 -> AI匹配 -> 标准履约 -> 质量回传 -> 晋级/复训/降级`

平台同时提供两条收入链：

- 服务交易：护理服务费、平台技术服务费、IoT设备服务、增值保障。
- 人才成长：社会化课程费、实操考核费、年度复训/复审、机构团培。

## 3. 双轨能力证明

### 3.1 法定资质与材料核验

独立展示实名身份、护士执业注册、专业技术资格、教育与专业经历。平台只描述核验状态，不自行创造法定资格。

### 3.2 平台内部能力等级

| 等级 | 角色 | 规则摘要 |
| --- | --- | --- |
| P0 | 见习 | 培训/带教中，不得独立接单 |
| M1 | 基础护理员 | 低风险基础照护、标准记录 |
| M2 | 专业护理师 | 常规居家服务；含餐/IoT需专项认证 |
| M3 | 高级护理师 | 复杂常规场景、高级专项与稳定履约 |
| M4 | 专家督导 | 联合评估、带教、考核和质量复盘 |

任何等级都不授予诊断、处方或超范围医疗操作权限。

### 3.3 五维考核

- 母婴专业照护30%：产褥期生活护理、新生儿日常护理、喂养、安全睡眠。
- 营养与月子餐20%：膳食计划、食品安全、烹饪、特殊饮食沟通。
- 家政服务规范15%：母婴区域清洁、消毒、洗护、用品与服务边界。
- 风险识别与升级20%：红旗症状、急救基础、复测、转诊和平台上报。
- 沟通与履约15%：隐私、日志、冲突处理、准时、满意度和投诉。

采用理论、技能站、家庭情景、带教订单和历史履约组合评价。设置安全否决项，重大违规可暂停或撤销。

## 4. 两类服务模式

### 专业照护·不含餐

包含母婴照护、观察记录、喂养支持、母婴用品整理和家庭照护指导；不包含备餐和其他家庭成员家务。

### 全程照护·含餐

在专业照护基础上增加产妇三餐两点、食品安全记录和厨房收尾。合同需明确食材提供/采购方式、特殊膳食、其他家庭成员餐食和额外家务。

### 签约原则

- 页面不能只显示套餐名，必须显示包含项、排除项、食材规则和变更规则。
- 需求选择含餐时，匹配硬门槛要求护理师含餐专项认证有效。
- 每日确认分别验收母婴照护、餐饮、日志和设备复核，避免用单一“已完成”掩盖缺项。

## 5. IoT智能照护

### 数据来源

- 产妇：消费级智能手环，可记录心率、血氧、腕温和睡眠趋势。
- 新生儿：体温计、智能体重秤、喂养/排泄人工记录；设备适用范围需单独核验。
- 护理师：记录测量条件、人工复测、症状问询和处置结果。

### 预警闭环

1. 设备采集并标记数据质量。
2. 规则/模型结合个人基线和持续趋势生成关注提示。
3. 护理师在SLA内问询、复测和判断是否升级。
4. 紧急红旗直接提示120/急诊；非紧急风险可建议线下就医或生成平台工单。
5. 复核和最终结论回传规则评估，减少无效预警。

### 必要合规控制

- 健康和设备数据采用单独、明确、可撤回授权，按目的最小化采集。
- 消费级设备不得被描述为诊断工具；医疗用途设备核验注册/备案与适用范围。
- 保留原始读数哈希、规则版本、数据质量、人工复核、通知与升级日志。

## 6. 培训商业化

### 课程产品

| 产品 | 目标 | 原型演示价 |
| --- | --- | ---: |
| 医护人员转型训练营 | M1到M2，理论、实操、带教 | 1980元 |
| 产后营养与月子餐实操 | 含餐专项认证 | 899元 |
| 母婴家庭服务与家政规范 | 家政边界与实操 | 599元 |

实际定价需通过试点验证获客成本、师资/场地成本、完成率、退款率和晋级后的订单收入提升。

### 课程与订单联动

- 基线测评和低分维度自动生成学习建议。
- 课程通过后不能直接无限期生效，应设置有效期、带教和订单观察期。
- 投诉、日志缺项、IoT复核超时和餐饮履约差可触发专项复训。
- 课程推荐要避免“付费即升级”，证书发放必须与独立考核结果绑定。

## 7. AI匹配改造

先执行硬门槛，再进行可解释排序：

- 硬门槛：法定材料、平台状态、风险胜任、专项认证、区域、日期、班次和预算。
- 专业适配：母婴照护、营养餐、家政、风险、沟通五维成绩。
- 履约预测：同类订单评分、取消、迟到、日志、投诉和异常复核。
- 本地适配：距离、通勤稳定性、本地院校/机构经历和语言沟通。

推荐结果须显示主要加分项、潜在限制、证书性质、数据更新时间和用户可调整权重。

## 8. 核心指标

- 供给：入学到认证转化率、各等级人数、含餐/IoT专项覆盖率、复审通过率。
- 交易：需求到匹配、匹配到签约、含餐选择率、IoT选购率、客单价和复购率。
- 质量：按时到达、日志完整、餐饮完成、预警复核SLA、投诉率、退款率和重大异常率。
- 培训：招生收入、获客成本、完课率、考核通过率、退款率、晋级后接单和收入提升。
- 模型：硬门槛误拦截、推荐接受率、解释点击、预警准确性和人工推翻率。

## 9. 实施优先级

### Phase 1：8-10周

认证模型、课程与考核后台、含餐/不含餐合同、规则匹配、护理日志和人工预警工单。

### Phase 2：6-8周

接入单一手环/体温设备供应商、数据授权、趋势看板、人工复核SLA和培训支付。

### Phase 3：持续迭代

满意度/履约风险预测、课程推荐、认证动态调整和多地区规则配置。

## 10. 原型验收标准

- 首页可进入认证中心、IoT监测和成长学院。
- AI采集至少覆盖12个专业模块，包含餐饮和设备偏好。
- 护理师库可按含餐与IoT能力筛选，详情展示等级证书、有效期和五维成绩。
- 签约页切换含餐/不含餐时范围和价格实时更新，IoT附加项可开关。
- IoT页可切换产妇、新生儿和设备，预警可触发人工复核反馈。
- 培训课程可触发报名反馈，护理师端展示晋级缺口。
